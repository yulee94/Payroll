# Backend Contract Requests

The production direction is Rust backend contracts plus TypeScript frontends. Repo-owned Python is decommissioned; missing historical behavior must return through Rust/Buck2 services or TypeScript contracts only.

The current browser runtime consumes the Rust-owned `/api/platform/v1/view-model` payload generated by `crates/payroll-api/src/platform_view.rs` and `crates/payroll-api/src/bin/platform_live_view.rs`.

Frontend integration should keep stable read-only view models for:

- Current tenant/session display info
- Platform navigation permissions by user role
- Payroll readiness cards or snapshot
- Payroll setup policy display values
- Recent payroll periods and archive file summaries
- Workflow inbox counts and document state summaries
- HR summary counts for roster, attendance, and certificate requests
- Archive folder/category summaries
- AI recommendation availability by screen
- Admin user/role summary counts
- User appearance and notification preferences

If a backend field is not available yet, render an explicit contract-missing or readiness-blocked state from Rust. Do not add mock data, demo credentials, or Python bridge code to fill the UI.
