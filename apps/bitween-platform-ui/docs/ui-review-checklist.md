# Bitween Frontend UI Review Checklist

이 문서는 Bitween React Native/Web 준비 화면을 검토할 때 사용하는 frontend 전용 체크리스트입니다. 급여 계산, 세금/공제, 파일 저장, 권한, API, 서비스, 운영 데이터 로직은 검토 대상이 아니며 코드 변경 대상도 아닙니다.

## 기본 원칙

- 변경 파일은 `apps/bitween-platform-ui`, `assets`, frontend 계약/문서 범위 안에 머문다.
- Rust backend crates, 운영 `config`, `templates`, `users`, `output`, `workspace` 데이터는 frontend-only 검토에서 수정하지 않는다.
- backend 데이터가 부족하면 서비스 파일을 바꾸지 않고 PR 설명의 `Backend Requests`에 요청사항으로 남긴다.
- 화면은 B2B 업무 플랫폼답게 차분하고 스캔하기 쉬워야 한다.
- 버튼, 탭, 필터, 테이블, 상태 배지, 빈 상태, 오류 상태는 같은 규칙으로 보이게 한다.
- 텍스트가 버튼, 카드, 표 셀 안에서 잘리거나 겹치지 않아야 한다.

## 실행

- 로컬 브라우저 셸은 `apps/bitween-platform-ui`에서 `npm run live`로 실행한다.
- 브라우저에서 `http://127.0.0.1:4174/` 또는 `http://localhost:4174/`을 연다.
- `/api/platform/v1/view-model` 응답이 `backend: rust_native`이고 준비 상태·차단 항목·다음 행동이 Rust 응답에서 렌더링되는지 확인한다.
- 인증이 필요한 기능은 데모 계정으로 우회하지 않고 명시적인 readiness-blocked 또는 contract-missing 상태로 보여야 한다.

## 공통 Shell

- 좌측 상단에 Bitween 회사 로고가 선명하게 보인다.
- 우측 상단 로그아웃 영역 근처에 사용자 사번이 보인다.
- 사이드 메뉴는 현재 선택 상태가 분명하고 색상 옵션 적용 후에도 대비가 충분하다.
- 사이드 메뉴 라벨은 현재 언어 설정에 맞는 표시명만 보여야 한다.
- 각 메뉴 진입 시 상단은 main title 중심으로 간결하게 보이고 불필요한 subtext가 시선을 방해하지 않는다.
- 작은 창, 태블릿 폭, 데스크톱 폭에서 메뉴와 본문이 겹치지 않는다.

## 홈 / 런처

- 플랫폼 홈 상단에서 달력과 to-do list를 바로 볼 수 있다.
- 오늘 해야 할 업무는 계속 보이고, 이미 실행한 업무는 연하게 표시된다.
- 빠른 실행 버튼은 다음 행동을 명확히 보여준다.
- 업무 카드의 숫자, 상태, 설명이 한눈에 구분된다.
- 빈 상태나 데이터가 적은 상태에서도 화면이 허전하거나 깨져 보이지 않는다.

## 급여

- 급여 준비 현황, 연동 준비, 확인 필요 항목이 상태 배지와 카드로 구분된다.
- 급여 산출 공식, 세금, 공제, 파일 저장 흐름은 frontend 변경으로 건드리지 않는다.
- 기존 조회성 서비스 결과가 있으면 화면 표시만 사용하고 서비스 내부 구현은 수정하지 않는다.
- 준비 미완료 상태에서는 사용자가 다음에 확인할 항목을 알 수 있어야 한다.
- `Branch 권한 확인` 같은 이동 버튼은 관련 화면으로 자연스럽게 연결된다.

## HR / 채용

- HR 화면은 직원명부, 이력서, 사직서, 재직증명서, 경력증명서 관리 범위가 명확히 보인다.
- 채용 화면은 지원자 경력, 자격, 부서 배치 후보를 부서가 이해하기 쉽게 정리한다.
- 필터, 검색, 상태 배지는 목록이 많아도 빠르게 스캔할 수 있어야 한다.
- 선택한 사람 또는 문서의 상세 패널은 주요 정보와 다음 행동만 남긴다.

## 전자결재 / 출퇴근 / 출장

- 결재 화면은 대기, 진행, 반려, 완료 상태가 분명하다.
- 출퇴근 화면은 오늘 상태, 출근/퇴근 버튼, 최근 기록, 관리자 확인 상태를 구분한다.
- 출장/업무일지 화면은 출장계획, 출장실행, 업무일지, 실적반영, 상급자 확인 흐름이 순서대로 이해된다.
- 모바일 폭에서도 주요 버튼이 누르기 쉬운 크기와 간격을 가진다.

## 자료함 / AI / 관리자 / 설정

- 자료함은 보관함, 접수한 파일, 검토가 필요한 항목, 저장 전 확인 흐름을 분리해서 보여준다.
- 자료함의 인사/급여 자료 접수는 헤더 행 선택, 필드 매핑, 정규화 힌트, 명시적 무시/보존 결정을 실제 저장 흐름과 연결해야 하며 죽은 버튼이나 설명뿐인 항목을 남기지 않는다.
- AI 화면은 추천, 요약, 초안, 사람 검토 필요 상태를 backend 호출 없이 frontend 표시 상태로만 다룬다.
- 관리자 화면은 법인 Branch, 하위계정, 권한 매트릭스가 업무 담당자에게 읽기 쉬워야 한다.
- 설정 화면은 국제화, 화면 표시, 계정 관련 설정을 사용자가 찾기 쉽게 배치한다.
- 현재 브랜치에 없는 backend 연동 설정은 명시적인 backend 요청사항으로만 남긴다.

## 반응형 및 접근성

- 360px, 768px, 1186px 이상의 폭에서 텍스트와 버튼이 겹치지 않는다.
- 표가 좁은 화면에서 깨지면 카드형 목록이나 가로 스크롤 같은 대체 흐름을 확인한다.
- 활성, 비활성, 오류, 완료, 경고 상태는 색상만이 아니라 텍스트로도 구분된다.
- 버튼에는 사용자가 예상하는 동작이 담겨 있어야 하며, 죽은 버튼은 남기지 않는다.
- 스크롤 가능한 영역은 헤더, 사이드바, 하단 영역과 충돌하지 않는다.

## PR 증빙

PR 설명에는 다음 항목을 남긴다.

- `Changed Screens`: 변경된 화면과 사용자가 보는 차이.
- `Tests`: 로그인, 홈, 사이드 메뉴 이동, 급여, 설정, 변경 화면 버튼/탭/스크롤 확인 여부.
- `Backend Safety`: backend/payroll 계산/서비스/데이터 파일을 수정하지 않았다는 확인.
- `Backend Requests`: 필요한 backend 요청사항이 없으면 `없음`, 있으면 화면별로 구체화.

가능하면 다음 검증을 실행한다.

- `git diff --check`
- `node --check preview/app.js`
- `npm run typecheck`는 `npm`과 `node_modules`가 있는 환경에서 실행한다.
- 자료함 접수/매핑/저장 흐름을 바꾸면 `npm run verify:archive-intake-stories`를 실행해 실제 UI 사용 경로의 정상 ZIP 업로드, 빈/불완전 파일 edge case, 악의적 ZIP 항목 거부, 잘못된 매핑 변경 거부, 시각적 매핑 편집 affordance가 퇴행하지 않았음을 확인한다.
