# Bitween Rust Live Browser Runtime

This folder serves the dependency-free browser shell for local product review.
The preview is Rust-backed: `/api/platform/v1/view-model` is generated by the
Buck2 target `//crates/payroll-api:platform_live_view`. HR and 자료함 write
paths fail closed unless relational persistence is configured; local JSON
persistence is only available behind the explicit hermetic review flag
`BITWEEN_ALLOW_LOCAL_REVIEW_STORE=true`.

## Run

```bash
npm run preview
# or
npm run live
```

The server listens on `http://127.0.0.1:4174` and serves:

- static UI assets from this folder
- `/catalog.json` from the TypeScript i18n catalog
- `/api/platform/v1/view-model` from `buck2 run //crates/payroll-api:platform_live_view`
- `/api/hr/v1/employees` from `buck2 run //crates/payroll-api:hr_employee_store`
- `/api/archive/v1/intake` from RustFS + `buck2 run //crates/payroll-api:archive_intake_store`
- `/api/settings/v1/preferences` from `buck2 run //crates/payroll-api:user_preference_store`
- `/api/auth/v1/routes` as the signed-out route availability contract
- `/api/auth/v1/signin`, `/api/auth/v1/signup`, `/api/auth/v1/signout`, and `/api/onboarding/v1/start`
  as configured identity/onboarding route starters

## Live configuration

Set these environment variables before running the server to clear production-readiness blockers:

- `BITWEEN_TENANT_ID`
- `BITWEEN_TENANT_NAME`
- `BITWEEN_PAYROLL_AFFILIATE`
- `BITWEEN_PAYROLL_WORKPLACE`
- `BITWEEN_PAYROLL_PERIOD`
- `BITWEEN_AUTH_CONFIGURED=true`
- `BITWEEN_SESSION_JWT_VERIFIED=true`
- `BITWEEN_SESSION_JWT_ISSUER=https://auth.example.com`
- `BITWEEN_SESSION_JWT_AUDIENCE=bitween-platform`
- `BITWEEN_SESSION_JWT_SUBJECT=<stable-user-subject>`
- `BITWEEN_SESSION_JWT_EXPIRES_AT_UNIX=<future-unix-seconds>`
- `BITWEEN_WEBAUTHN_USER_VERIFIED=true`
- `BITWEEN_SESSION_ACR_LEVEL=elevated`
- `BITWEEN_SESSION_ACR_EVENT_AT_UNIX=<acr-grant-unix-seconds>`
- `BITWEEN_SESSION_ROLE=<role-family>`
- `BITWEEN_SESSION_AUTHZ_POLICY_ID=bitween.authz.rbac-abac-pbac.v1`
- `BITWEEN_SESSION_AUTHZ_TENANT_ID=<authorized-tenant-id>`
- `BITWEEN_SESSION_AUTHZ_LEGAL_ENTITY=<authorized-legal-entity>`
- `BITWEEN_SESSION_AUTHZ_WORKPLACE=<authorized-workplace>`
- `BITWEEN_ARCHIVE_CONFIGURED=true`
- `BITWEEN_ONTOLOGY_CONFIGURED=true`
- `BITWEEN_WORKFLOW_CONFIGURED=true`
- `BITWEEN_COMPLIANCE_PACK_CONFIGURED=true`
- `BITWEEN_OBSERVABILITY_CONFIGURED=true`
- `BITWEEN_FINOPS_CONFIGURED=true`
- `BITWEEN_IMPORT_PLAN_DECLARED=true`
- `BITWEEN_SUPPORT_RUNBOOK_CONFIGURED=true`

자료함 upload requires a live self-hosted RustFS/S3-compatible endpoint:

- `BITWEEN_RUSTFS_ENDPOINT=http://127.0.0.1:9000`
- `BITWEEN_RUSTFS_ACCESS_KEY=<access key>`
- `BITWEEN_RUSTFS_SECRET_KEY=<secret key>`
- `BITWEEN_RUSTFS_BUCKET_ARCHIVE=bitween-archive-originals`
- `BITWEEN_RUSTFS_REGION=us-east-1`

Production relational write paths require PostgreSQL. HR, 자료함, Settings, and
업무 관리 endpoints use the Rust Buck2 stores when `BITWEEN_POSTGRES_DSN` plus
tenant/legal-entity/workplace scope are configured, and fail closed with
redacted errors when PostgreSQL is unavailable. File-backed persistence is
limited to explicit hermetic product review:

- `BITWEEN_ALLOW_LOCAL_REVIEW_STORE=true`
- `BITWEEN_HR_EMPLOYEE_STORE=.bitween/local-review/hr/employees.json`
- `BITWEEN_ARCHIVE_INTAKE_STORE=.bitween/local-review/archive/intake.json`
- `BITWEEN_USER_PREFERENCE_STORE=.bitween/local-review/settings/preferences.json`

The browser cannot authenticate itself. Sign-in, access request, onboarding, and
sign-out buttons only start configured provider routes:

- `BITWEEN_AUTH_SIGNIN_URL=https://auth.example.com/signin`
- `BITWEEN_AUTH_SIGNUP_URL=https://auth.example.com/request-access`
- `BITWEEN_AUTH_SIGNOUT_URL=https://auth.example.com/signout`
- `BITWEEN_ONBOARDING_START_URL=https://onboarding.example.com/start`

The shell enters the app only when the Rust live payload reports provider
configuration, verified JWT registered-claim facts, a future expiration, and
WebAuthn/passkey user verification with a controlled ACR event. Sensitive
operations are additionally checked in Rust with ABAC + RBAC + PBAC: role,
tenant/legal-entity/workplace scope, data class, trusted policy id, workflow
state, and step-up level must all pass. Missing identity routes return
`auth_route_unconfigured` at the API boundary; the signed-out UI preflights
`/api/auth/v1/routes` and disables unavailable actions so operators are not sent
into a missing-address toast. These routes do not create local browser sessions.
Sensitive HR, 자료함 intake, and Settings read/write routes call
`buck2 run //crates/payroll-api:authz_decision` before any local-review store
read/write or RustFS object upload. Denied decisions return `authorization_required`.

When a prerequisite is missing, the UI must show it as a business blocker or a
recoverable upload failure rather than inventing data.

## HTTP hardening

The local live server sends no-store caching plus security headers on static,
JSON, error, and live-reload event-stream responses: CSP, frame blocking,
MIME-sniff blocking, no-referrer, permissions-policy denial, and same-origin
opener/resource isolation. Keep these headers guarded by `npm run verify:data-mode`.

## Palette discipline

Preview runtime accents and tone colors are pulled from CSS palette variables,
and the TypeScript app uses `src/theme.ts` palette tokens. The palette is based
on Pantone direction: Cloud Dancer-style neutral surfaces with
Marina/Alexandrite/Burnt Sienna/Amaranth-inspired operational accents adjusted
for enterprise contrast. Do not add ad-hoc hex or rgba colors to preview JS,
navigation data, React components, or preview CSS component rules.
